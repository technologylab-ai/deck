Install & use the deck Stream Deck plugin

Put a button on your Stream Deck that opens or focuses an app or browser tab on the right AeroSpace workspace — tap to open, hold to close. This is the practical how-to; the design record covers the why.

Platform: macOS · AeroSpace · Elgato Stream Deck 6.5+  |  You need: the deck CLI installed, Node 20+, the Stream Deck app.

1What you get

One Stream Deck action — Open Target — that you drop onto a key and point at a target from your deck config. Once set, the key:

  • shows the right icon automatically (the site’s favicon for a browser tab, the app icon for a native app);
  • on a tap, opens the target — or, if it’s already open, just focuses it — and switches AeroSpace to its workspace;
  • on a long-press (hold ~0.5s), closes it — quits the app, or closes the matched browser tab.
The one thing to know The plugin is a thin wrapper around the deck command-line tool. The buttons just run deck open / deck close for you. So if deck works in your terminal, the buttons work — and everything you configure lives in one file, ~/.config/deck/targets.toml.

2Before you start

Make sure these three things are true. Run the checks in a terminal:

  • The deck CLI is installed at ~/.local/bin/deck (via uv tool install --editable . in the repo). Verify:
deck doctor          # should report config, aerospace, osascript all ✓
deck list            # should print your configured targets
  • Node.js 20 or newer is available (only needed to build the plugin — the Stream Deck app supplies its own Node at runtime): node --version.
  • The Elgato Stream Deck app is installed and running (version 6.5 or newer).
Why the absolute path matters Stream Deck launches commands with a stripped-down PATH that does not include Homebrew. The plugin always calls deck by its full path ~/.local/bin/deck, so that shim must exist. If deck doctor works but buttons don’t, this is the usual cause — see Troubleshooting.

3Install the plugin

From the repo root, build the plugin and link it into Stream Deck. You only do this once (and again whenever you change the plugin’s own code).

  1. Build it. 
    cd streamdeck-plugin
npm install
npm run build
    This produces ai.technologylab.deck.sdPlugin/bin/plugin.js. (The repo already ships a built copy, so you can skip straight to linking if you haven’t touched the plugin source.)
  2. Install the Elgato CLI (gives you the streamdeck command): 
    npm i -g @elgato/cli
  3. Enable developer mode. Required — without it Stream Deck silently refuses to load a linked plugin. 
    streamdeck dev
  4. Link the plugin. 
    streamdeck link ai.technologylab.deck.sdPlugin
    Stream Deck loads it immediately. You should now see a deck category in the actions list (right-hand panel of the Stream Deck app).
Did it load? In the Stream Deck app, the actions list (top-right) should show a deck category containing Open Target. If it’s there, you’re done installing.

Updating later

After editing plugin source, rebuild and restart it:

npm run build
streamdeck restart ai.technologylab.deck

Changes to your targets (in targets.toml) need none of this — see Add a new target.

4Add a button

  1. In the Stream Deck app, find deck → Open Target in the actions list and drag it onto a key.
  2. With the key selected, the settings panel below shows a Target dropdown. Open it — it’s populated live from your config — and pick a target (e.g. hey, synadia-gmail, outlook).
  3. The key’s icon updates automatically: a favicon for web targets, the app icon for native apps.
  4. (Optional) The Title field is pre-filled with the target name. Edit it to relabel the key, or clear it for no title (icon only). Pick a different target and the title follows along — unless you’ve customized it, in which case your text is kept.
No icon appeared? The icon comes from deck icon <target>. Web icons need network access the first time (they’re cached afterward). If a key stays blank, run deck icon <target> in a terminal to see the error — details in Troubleshooting.

5Using a button

GestureWhat happensRuns
Tap Opens the target if it isn’t open; otherwise just focuses the existing window/tab. Either way, AeroSpace switches to its workspace. deck open <target>
Long-press
hold ~0.5s		 Closes the target: quits a native app, or closes the matched browser tab. Releasing after the press is registered does nothing else. deck close <target>

The key flashes a green ✓ on success or a yellow ⚠ if something went wrong (e.g. a permission prompt is waiting, or no target is selected).

Close quits the whole app For a native target, a long-press quits the app (all its windows), mirroring Stream Deck’s built-in app toggle. For a browser target it closes only the one matched tab.
First press is special The very first time a button touches Chrome, Safari, or quits an app, macOS shows a one-time permission prompt — approve it and press again. See Permissions.

6Add a new target

This is the payoff: adding a target never touches the plugin. Edit one file and it shows up in the dropdown.

  1. Open ~/.config/deck/targets.toml and add a table. For a web tab: 
    [notion]
browser = "chrome"            # safari | chrome
url = "https://notion.so"
workspace = "2"               # an AeroSpace workspace name
match = "notion.so"           # dedup substring (defaults to url)
  2. For a native app, first look up its bundle id with deck bundle <name> — it resolves an app name (matching fuzzily) to the bundle id and path: 
    $ deck bundle slack
App    Bundle ID                  Path
Slack  com.tinyspeck.slackmacgap  /Applications/Slack.app
    Then add the app target with that bundle id: 
    [slack]
type = "app"
bundle = "com.tinyspeck.slackmacgap"
workspace = "2"
  3. Test it in the terminal: deck open notion (or deck open slack).
  4. In the Stream Deck app, select your Open Target key and re-open the Target dropdown — the new target is there. Pick it; the icon appears. No rebuild, no relink.
deck bundle handles the tricky names Bundle ids often aren’t what you’d guess: deck bundle teams → com.microsoft.teams2, deck bundle telegram → ru.keepcoder.Telegram. A fuzzy query lists every matching app with its id and path, so you can copy the right one.

Open on the current workspace

Instead of a fixed workspace number, set workspace = "current" to open a target wherever you happen to be — and leave it there (no move). Good for a “summon it near me” app like ChatGPT:

[chatgpt]
type = "app"
bundle = "com.openai.chat"
workspace = "current"

What counts as “already open” differs by type:

  • App targets are global. If the app is running anywhere, a press focuses it where it lives; otherwise it launches on your current workspace. (Re-launching an app just re-activates its existing window, so “go to it” is the only sensible move.)
  • Browser targets are workspace-local. Only a matching tab on the workspace you’re on counts. A matching tab on another workspace is ignored — so a press opens a fresh one here instead of yanking you to wherever an old tab happens to live.
Why browser is workspace-local If you keep several tabs of the same site open (say a few Gemini conversations on different workspaces), a global match would always pull you to one of those when you just wanted a fresh one here. Workspace-local current gives you “Gemini, right here” every time.

Browser targets open as tabs (one window per workspace)

When deck has to create a browser target (it isn’t already open), it adds it as a new tab in the browser window already on that workspace — and only opens a separate window if that workspace has no browser yet. So if you park five Chrome or Safari targets on one workspace, you get one window with five tabs instead of five windows.

Tab vs. window The first browser target you open on an empty workspace creates the window; every one after that lands as a tab in it. Mixed Chrome + Safari on the same workspace stay separate (one Chrome window, one Safari window) — consolidation is per browser.

7Permissions

Driving Chrome/Safari and quitting apps happens through macOS Automation (Apple Events). Because the plugin runs inside the Stream Deck app, macOS attributes these to Elgato Stream Deck — so you grant access once per controlled app, not once per button.

  • The first time a button opens/closes a Chrome target: approve “Elgato Stream Deck wants to control Google Chrome”.
  • Same for Safari, and the first time a long-press quits a native app.
  • AeroSpace placement uses a plain CLI call — no permission prompt.

You can review or toggle these later in System Settings → Privacy & Security → Automation. To check status from the terminal:

deck doctor          # reports Automation for the browsers your targets use
Only open/close need permission The config helpers send no Apple Events and never prompt: deck list, deck icon and deck bundle all use Spotlight / Launch Services, not AppleScript. Only deck open and deck close drive an app, so those are the only ones that can trigger an Automation prompt.
There is no “allow all” switch macOS Automation is intentionally per-app: the list under Privacy & Security → Automation only shows pairs you’ve already been prompted for, so you can’t pre-approve every app at once. Approve each controlled app the first time you press its button. If you denied one by accident the button flashes ⚠ and does nothing — re-enable Elgato Stream Deck → <app> there and press again.

8Troubleshooting

SymptomLikely cause & fix
Open Target isn’t in the actions list Developer mode off, or the link didn’t take. Run streamdeck dev, then streamdeck restart ai.technologylab.deck. Confirm the plugin is linked under ~/Library/Application Support/com.elgato.StreamDeck/Plugins/.
Dropdown is empty deck list --json failed. In a terminal, run it: if it errors, fix your targets.toml (deck doctor pinpoints the problem). Also confirm ~/.local/bin/deck exists.
Button flashes ⚠ and nothing opens Usually a pending/denied Automation prompt (see Permissions), or no target selected. Check the plugin log (below) for the exact deck exit.
Key shows no icon Run deck icon <target> in a terminal. Web icons need network on first fetch; app icons need the app installed. Force a rebuild with deck icon <target> --refresh.
App opens on the wrong workspace deck waits for the new window, then moves it. A very slow cold-start can still surprise you on the rare edge; just press again, or pin the app statically with an on-window-detected rule (see aerospace-snippet.toml).
Wrong Chrome window/tab gets focused Expected only if your real browsing happens in a non-default Chrome profile — deck targets the default profile by design. Move the tab there, or keep Synadia in Safari / personal in Chrome as intended.

Reading the plugin log

The plugin writes its own log next to the build:

tail -f streamdeck-plugin/ai.technologylab.deck.sdPlugin/logs/*.log

deck itself logs to ~/.local/state/deck/deck.log.
